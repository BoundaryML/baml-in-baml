# Report duplicate fields in class literals

Upstream: https://github.com/BoundaryML/baml/pull/5719

## Intent

A class literal that names a field twice (`Pair { a: null, a: 1 }`) was
accepted, last value winning. It now reports E0012 "duplicate field `a` in
class literal", the first site as a secondary annotation ("first set here")
and each repeat as a primary ("set again here"), like class patterns do. A
field that also comes from a `...spread` is not a duplicate.

## Acceptance

`baml_tests/projects/diagnostic_errors/duplicate_object_field` and its
`05_diagnostics.snap`. Ported ahead of the merge: `ns_hir/builder.baml`
(the `ExprObject` arm), `ns_hir/diagnostic.baml`
(`Hir2DiagnosticDuplicateObjectField`), test
`ns_hir/duplicate_object_field_test.baml` pinned to the PR snapshot (labels
and byte spans checked). Once the oracle toolchain includes #5719, the corpus
