# Phase 1, micro level: porting the emitter

`MIGRATION.md` says what to build. This says how the work actually happens,
one function at a time, and where it would otherwise break.

## Where the macro plan breaks

| # | Failure | Why it happens |
|---|---|---|
| F1 | "Package bytes differ at offset 48213" | Byte-equality on a whole borsh blob gives no location. Nobody can debug from it. |
| F2 | The exporter is never complete | Emit makes ~70 kinds of frontend calls, some implicit (stdlib lanes, precompiled interfaces, test exclusion, opt level). Designing `LoweredPackage` by reading code misses some, and each miss surfaces late as a wrong byte. |
| F3 | Hand-written type mirrors drift | MIR (~30 types, ~120 variants), `CompilationUnit`, bytecode (~300 instruction variants) and ~150 borsh types must be mirrored in BAML exactly. Hand-written mirrors and encoders will be wrong in small ways, and upstream changes them weekly. |
| F4 | Translation is inconsistent | 16k lines ported by many agents, each choosing its own way to express `HashMap` iteration, `u32` math, `Option`, data enums, `&mut` helpers. The result is unreviewable and diverges subtly. |
| F5 | No unit of work | "Port emit" is not a task. Agents need pieces small enough to finish and check in one sitting. |
| F6 | The target moves | Emit changes several times a week. A port that chases canary never converges. |
| F7 | Surprises arrive late | VM speed, stack depth, a 120-variant union's compile time, or a missing primitive found after 8k lines are ported. |

Each section below answers one or more of these.

## 1. Pin the baseline (F6)

The initial port targets one frozen upstream commit, `BASE` (recorded in
`bib/emitter/BASE`). Sync keeps mirroring canary, and emit-touching PRs after
`BASE` queue as port tasks as usual. When the emitter passes its gate at
`BASE`, the queued tasks are replayed in order, and `BASE` advances to each
one's commit. We never port against a moving tree.

## 2. Generate every mirrored type (F3)

`bib/crates/bib_typegen`: reads Rust type definitions with `syn` and generates
three things from one list of root types:

1. **BAML classes** for each struct and one class per enum variant, plus a union
   alias per enum (`type Rvalue = Rvalue_Use | Rvalue_BinaryOp | ...`).
2. **Rust exporters** (`impl ToBib for T`, a trait the fork owns, so the orphan
   rule allows it on upstream types): Rust value → JSON. This is how MIR leaves
   the Rust compiler without editing `baml_compiler2_mir`.
3. **BAML borsh writers** for output types (`CompilationUnit`, `Object`,
   `Instruction`, ...): BAML value → `uint8array`, field order and integer widths
   taken from the Rust definition. No Rust glue at all on the output side.

Roots: `baml_compiler2_mir::ir`, `baml_linker_types`, `bex_vm_types`, plus the
hir_ty types emit reads (layouts, signatures, impl facts). Generated files are
checked in under `bib/compiler/baml_src/gen/` and `bib/crates/bib_export/src/gen/`
and regenerated by sync when a root file changes; the regenerated diff goes
into the port task. Type changes upstream then become mechanical; only the
logic that uses them needs a port.

Things the generator must decide once, centrally: `usize`/`u32`/`u64` → `int`
with range checks in writers; `Vec<T>` → `T[]`; `Option<T>` → `T?`;
`IndexMap<K,V>` → `Entry<K,V>[]` (order matters, BAML maps don't promise it);
`HashMap` → `map` only where emit never iterates it (the generator flags it);
`Box`/`Arc`/lifetimes erased; salsa ids → `DeclPath`.

## 3. Grow the input by demand, with a ledger (F2)

`LoweredPackage` is not designed up front. It starts as: package identity,
declaration lists, and MIR bodies. Whenever a ported function needs a fact the
input lacks, the porter:

1. adds a field to `LoweredPackage` (BAML side, by hand: this is the one type we
   design rather than mirror),
2. fills it in the exporter from the exact Rust call that emit makes,
3. adds a row to `bib/emitter/INPUTS.md`: Rust call site → field → who reads it.

The ledger is the boundary's documentation and its completeness check: a
script lists every frontend call in `baml_compiler2_emit` (by path, from the
`use` graph) and fails if any has no ledger row. When upstream adds a new call,
that script fails and the port task says so.

## 4. Diff at the smallest unit that exists (F1)

The output is already structured per function: `CompilationUnit.code` holds one
`Object` per function, and `bex_vm::debug::display_program` (what
`bytecode.snap` uses) prints a function as text, one instruction per line.

`bib diff <project>` therefore reports:

```
pkg user  fn lambda_owners.Retry.scaled     MATCH
pkg user  fn lambda_owners.Other.run        DIFF  line 5: want `load_var2 2 1`, got `load_var 2` / `load_var 1`
pkg user  objects.classes[3]                DIFF  field `fields[1].ty`
pkg user  exports                           MATCH
```

Order of comparison: decoded structure first (classes, enums, exports, imports,
per-function bytecode as text), raw bytes last. A byte mismatch with a full
structural match is a writer bug, which the generator owns.

## 5. The unit of work is one Rust function (F5)

`bib/scripts/emit_graph.py` builds the call graph of `baml_compiler2_emit`
(syn, or rust-analyzer's SCIP dump) and writes `bib/emitter/graph.json`: every
function, its size, its callees, which file it lives in.

- A **task** is one Rust function (or a small strongly connected cluster),
  ported once all its callees are ported. Leaves first.
- Each BAML function keeps the Rust name and a header comment pointing at the
  Rust source (`// port of emit.rs:emit_switch @ BASE`), so a reviewer can
  read both side by side.
- **Pure helpers** (no MIR, no tables: numbering, line starts, operand
  encoding) get table-driven unit tests: inputs and expected outputs captured
  from Rust `#[test]`s in `bib_export` that call the same upstream `pub` items.
  Private Rust helpers are tested only through their callers.
- **Pipeline functions** are checked by `bib diff` on the ladder (below).

The port is finished when every node in the graph is ported and the gate passes.

## 6. One way to say each thing (F4)

`bib/emitter/IDIOMS.md` is the translation table every porter follows, and
`bib/compiler/baml_src/prelude/` holds the helpers it names. Settled before
the first port task:

| Rust | BAML |
|---|---|
| data enum + `match` | union of generated classes + exhaustive `match` |
| `Option<T>`, `?` on Option | `T?`, early `return null` |
| `Result<T, E>`, `?` | `throws E`, propagation |
| `HashMap` iterated in order-sensitive code | prelude `IndexMap` (array of entries + `map<K,int>` index) |
| `u32` / `usize` arithmetic | `int` + prelude `u32_checked` where Rust would panic |
| `&mut` out-params | return a value, or mutate a class field |
| `Vec::with_capacity`, `push` | `[]`, `push` |
| `String` building | `string[]` + `join` |
| `panic!` / `expect` | `panic` with the same message |
| deep recursion over blocks | explicit work-stack |

A new idiom is added to the table before it is used twice.

## 7. Spike the unknowns before building infra (F7)

Four spikes, each a day or less, each answering one question with a number:

| Spike | Question | Pass |
|---|---|---|
| S1 determinism | Does Rust emit produce identical bytes for the same input across runs and thread counts (parallel emit is on)? | identical on the whole corpus |
| S2 generator | Can `bib_typegen` turn `ir.rs` into BAML that compiles, and how long does the Rust compiler take on a 120-variant recursive union? | compiles, < 2s |
| S3 borsh | Does a generated BAML borsh writer reproduce one real `Object` byte for byte? | equal bytes |
| S4 speed | Port one real pass (`analysis.rs` def-use + predecessors) and run it on the largest corpus function on the VM. | within 50x of Rust |

If S4 fails badly, the plan changes (AOT the emitter via `baml_compiler2_rust`
early), so it runs first.

## 8. The ladder (progress you can see)

The corpus is sorted into rungs by which MIR features each project's functions
use (taken from the exported MIR, not guessed):

1. straight-line ints, calls, returns
2. branches, loops, `switch`
3. classes, fields, arrays, maps
4. unions, type tests, `match`
5. closures, cells, lambdas
6. throws, catch, defer
7. generics, interfaces, impls
8. globals, init order, multi-package imports
9. the rest of the corpus, then stdlib packages

`bib/emitter/SCORE.md` is regenerated after each run: functions matching / total,
per rung, per package. That number only goes up; a regression blocks a merge.

## 9. Scope cuts for phase 1

- `Scope::Package` only. Session submissions (`emit_session_submission`) later.
- User packages first. Stdlib packages are emitted by Rust until rung 9.
- `OptLevel` as the CLI defaults it. Other levels later.
- Parallel emit is irrelevant: the BAML emitter is serial and must match the
  serial output (S1 confirms they are equal).

## Order of work

1. S4, S1, S2, S3.
2. `bib_typegen` + generated types for MIR and outputs.
3. `bib_export` (MIR + minimal `LoweredPackage`), `bib diff` with decoded output.
4. `emit_graph.py`, `IDIOMS.md`, prelude.
5. Port leaves → roots, climbing the ladder. Agents can work in parallel on
   tasks whose callees are done, one file per agent at a time.
6. Gate at `BASE`; then replay queued emit ports to catch up with canary.
